# Pull requests

Scope: changes submitted for review.

- Use a concise Conventional Commit style title describing the final outcome. Link relevant issues in the description when available; do not require a particular tracker.
- Explain the problem, resulting behavior, validation performed, and material limitations. Include migration steps for incompatible changes.
- Prepare the complete description before creating a ready PR. Use a draft when required context or validation is still missing.
- Prefer small, focused changes and a single coherent commit. Multiple commits are acceptable when they improve review. Avoid unrelated cleanup.
- Keep your branch history linear and follow [branching](branching.md) when updating it.
- Report required checks accurately. Do not weaken validation to make a change pass.
- Address actionable review findings and explain the evidence for declined suggestions.
- Review AI-assisted changes with the same care as other contributions; disclose material unverified assumptions.
